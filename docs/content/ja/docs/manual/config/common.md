このページでは、AIRI のプロバイダー設定の仕組みを説明します。API アドレス、アカウントの準備、モデルの選択については、各プロバイダーのページを参照してください。

## 構成プロセス

1. **設定 → プロバイダー**を開き、**チャット**、**Vision**、**Speech**、**Transcription**、**Artistry**からカテゴリを選択します。
2. プロバイダーを選択し、ページで必要な資格情報を入力します。
3. 必要に応じて、詳細設定を展開し、プロバイダーが提供するベース URL またはその他のパラメータを入力します。
4. AIRI が検証を完了するまで待ちます。検証に合格したら、プロバイダーと、対応する機能モジュールのモデルまたはVoiceを選択します。

::: warning 認証情報のセキュリティ
資格情報とプロバイダー設定は、現在のデバイスのローカル設定に保存されます。スクリーンショット、ログ、問題、チャット ログなどで API キー、AccessKey Secret などの認証情報を決して開示しないでください。
:::

## 共通フィールド

|フィールド|意味|入力方法|
| --- | --- | --- |
| API Key |プロバイダーが発行するアクセストークン|引用符やスペースを追加せずに、完全なキーを直接貼り付けます。|
| Base URL |プロバイダーAPIのルートアドレス|プロバイダーのドキュメントで要求されている場合にのみ変更してください。カスタムアドレスを使用する場合は、完全な `https://` または `http://` アドレスを入力します。|
|モデル|チャット、音声、文字起こしに使用するモデル ID|AIRI のリストから選択します。手動入力が必要な場合は、プロバイダーのドキュメントに記載された正確な ID を使用します。|
|Voice|TTS が読み上げに使用する Voice ID|最初にモデルを選択し、そのモデルが対応する Voice を選択します。|
|リージョン|一部のクラウドサービスが使用するデプロイ先|プロバイダーコンソールのプロジェクトまたはリソースのリージョンと一致させます。|

## 検証結果

チャット プロバイダーは通常、ネットワーク接続、モデルのリスト、および簡単なチャット リクエストをチェックします。最後のアイテムは、少量のプロバイダー クレジットを消費する可能性があります。音声プロバイダーおよび音声認識プロバイダーは、対応するモジュールのテスト領域で実際の再生または認識結果を検証します。

検証が失敗した場合は、次の順序でトラブルシューティングを行ってください。

1. アカウントが対応するサービスをアクティブ化しており、利用可能なクレジットがあることを確認します。
2. API キーを再度コピーし、余分なスペースや改行がコピーされていないか確認します。
3. ベース URL をプロバイダーのデフォルト値に復元するか、プロバイダーの公式ドキュメントで逐語的に確認します。
4. ネットワーク、プロキシ、およびファイアウォールがプロバイダーへのアクセスを許可していることを確認します。
5. プロバイダーによって明示的にサポートされているモデルを選択します。表示名をモデル ID として使用しないでください。
