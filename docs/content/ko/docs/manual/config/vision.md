---

비전 모듈은 캡처한 이미지를 이미지 입력을 지원하는 모델로 보냅니다. 비전 제공자는 채팅 제공자와 같은 종류의 필드를 사용하지만, AIRI는 두 설정을 별도로 저장합니다. 비전 제공자 페이지에서 자격 증명을 다시 입력하세요.

::: info 왜 필드가 똑같아 보이나요?
같은 서비스가 채팅 모델과 이미지 이해 모델을 함께 제공하는 경우가 많아 양식이 동일한 필드를 사용합니다. 저장된 값은 서로 독립적이며, 이미지 입력을 명시적으로 지원하는 모델을 반드시 선택해야 합니다.
:::

::: warning 화면 비전을 사용하기 전에 Vision Capture를 활성화해야 합니다
비전 서비스 제공자와 모델만 설정하는 경우에는 이 도구를 활성화할 필요가 없습니다.

AIRI가 화면이나 창을 분석하게 하려면 **시스템 → 개발자 → Vision Capture**를 열고, 필요한 경우 화면 녹화 권한을 부여한 뒤 창이나 디스플레이를 선택하고 **Start ticker**를 클릭하세요. 결과를 현재 캐릭터에게 보내려면 **Publish to character**를 활성화하세요.

Vision Capture는 현재의 데스크톱 디버깅/개발 워크플로이며, 페이지를 벗어나면 캡처 루프가 중지됩니다. 전체 안내는 [데스크톱 개발자 도구](/ko/docs/contributing/desktop-developer-tools#vision-capture)를 참고하세요.
:::

## 비전 제공자 선택

1. **설정 → 제공자 → 비전**을 여세요.
2. 설정할 비전 제공자를 선택하세요.
3. 이 페이지에서 자격 증명을 입력하세요. API Key, Base URL, Azure 리소스 정보, AWS Region 등 필드는 채팅 제공자 버전과 동일하지만, 저장되는 값은 별개입니다.

필요하다면 채팅과 비전 양쪽에 같은 계정 자격 증명을 입력할 수 있습니다. 채팅 제공자에 자격 증명을 저장해도 비전 제공자에 자동으로 채워지지는 않습니다.

::: warning 이미지 및 자격 증명 보안
시각 분석은 캡처한 프레임을 선택한 제공자에게 전송합니다. API Key, 비밀번호, 개인 정보, 공유 권한이 없는 콘텐츠는 캡처하지 마세요. 클라우드 자격 증명은 절대 커밋하거나, 스크린샷으로 남기거나, 공유하지 마세요.
:::

## 비전 모델 선택

1. **설정 → 모듈 → 비전**을 여세요.
2. 방금 설정한 제공자를 선택하세요.
3. 이미지 입력을 지원하는 모델을 선택하세요.
4. **Capture interval**을 설정해 비전 티커가 프레임을 캡처하는 주기를 조절하세요.

데스크톱에서는 위에서 설명한 대로 현재 화면이나 창 소스를 **시스템 → 개발자 → Vision Capture**에서 별도로 선택합니다.

## 설정 확인

1. 민감한 정보가 없는 창을 캡처하세요.
2. 시각 분석을 실행하세요.
3. AIRI가 캡처된 프레임으로부터 설명이나 기타 컨텍스트를 받는지 확인하세요.

## 로컬 시각 모델

Ollama와 LM Studio를 로컬 비전 제공자로 사용할 수 있습니다. 이미지 입력을 지원하는 모델을 실행하고 AIRI가 해당 서비스에 접근할 수 있는지 확인하세요. 그런 다음 비전 제공자 페이지에서 해당 Base URL을 입력하거나 그대로 두고 **설정 → 모듈 → 비전**에서 모델을 선택하세요.

## 문제 해결

| 문제 | 해결 방법 |
| --- | --- |
| 제공자 유효성 검사가 통과되지 않음 | 채팅 제공자가 이미 설정되어 있어도 API Key, Azure Resource Name, AWS Region 등 비전에 필요한 필드를 모두 입력하세요. |
| 모델이 이미지를 분석하지 못함 | 모델이 이미지 입력을 명시적으로 지원하는지 확인하고 호환되는 비전 모델을 선택하세요. |
| 로컬 모델에 접근할 수 없음 | 로컬 서비스가 실행 중인지, Base URL·포트·CORS·LAN 접근 설정이 올바른지 확인하세요. |
| 요청이 거부되거나 할당량이 소진됨 | 계정 권한, API Key, 지역별 모델 제공 여부, 할당량, 네트워크 접근을 확인하세요. |
